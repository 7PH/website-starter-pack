# v5.1.7

- **Released:** 2026-09-25
- **Summary:** Patch. Email templates now reach sub-apps. Before this, none had synced since each app's first copy, which broke account deletion.

## Upgrade Notes

**Email templates will be overwritten.** All 10 files under `app/backend/src/templates/email/` sync on this upgrade. If you edited one in place, copy your changes aside first.

**Check `app/backend/src/router_app.py` by hand.** It is app-owned, so fixes to it never sync. v5.0.0 moved the auth router into the core router, but the template still registered it too. If your `router_app.py` has `router.include_router(auth.router, ...)`, delete that line: otherwise 8 auth routes are registered twice. While you are there, match the upstream template's `include_in_schema` flags so admin and flag-disabled routes stay out of the OpenAPI schema.

No schema, API, or migration changes.

## Bug Fixes

### Email templates never synced

The manifest listed `app/backend/src/templates/*`, but the update script only matches files directly in that folder, and every template lives in `templates/email/`. The entry matched nothing, so sub-apps kept whatever templates they started with:

- `account_deletion.{html,txt}` was missing. That email has no text fallback, so `POST /users/me/account-deletions` returned **502** and users could not delete their account.
- `conversation_reply.{html,txt}` (v5.1.6) was missing, so the reply email went out text-only.
- `password_reset` still said the link lasts 7 days; it has been 4 hours since v5.0.0.

The manifest now lists the directory, which syncs every file under it.
