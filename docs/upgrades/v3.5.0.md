# v3.5.0

- **Released:** 2026-05-13
- **Summary:** New `useNativeBridge` composable and `MOBILE_APP=1` build switch let sub-apps ship a Capacitor mobile wrapper without forking core. Stripe checkout, billing portal, and Google OAuth now route through the bridge so the wrapper can open them in the native browser instead of the in-app webview (required for Google OAuth, which blocks embedded webviews with `disallowed_useragent`). The "Continue with Google" button also shows in the auth modal, matching `/login`.

## Upgrade Notes

No breaking changes. Web behaviour is identical — `useNativeBridge()` returns a no-op stub on the web that falls through to the same `window.open` / `window.location.href` calls as before. Sub-apps that don't ship a mobile wrapper need no changes.

### Migration

None.

## New Core Files

- `app/frontend/composables/useNativeBridge.ts` — single entry point for talking to a Capacitor native shell.

## New Features

### `useNativeBridge` composable

Sub-apps shipping a Capacitor wrapper assign a real implementation to `window.__nativeBridge` from a client plugin; on the web (or when no wrapper is present), callers get a no-op stub. Callers don't branch on platform:

```ts
const bridge = useNativeBridge();
if (bridge.isNative()) {
    await bridge.openExternal(url);
} else {
    window.open(url, '_blank');
}
```

The minimal interface ships two methods: `isNative()` and `openExternal(url)`. Apps that need more (haptics, native audio, push, ...) extend it via TypeScript module augmentation — see the new "Mobile wrapper (Capacitor)" section in `README.md`.

Wired into:

- `useStripe.openBillingPortal` (Stripe customer portal)
- `useUserSubscription.subscribeToPlan` + `openBillingPortal` (user-account Stripe flow)
- `useOrganizationSubscription.subscribeToPlan` + `openBillingPortal` (org Stripe flow)
- `useOAuth.startGoogleOAuth` (Google sign-in — load-bearing; embedded webviews are blocked by Google)

### `MOBILE_APP=1` build switch

`MOBILE_APP=1 npm run build` produces a static SPA (`ssr: false`, `nitro.preset: 'static'`) suitable for bundling into a Capacitor wrapper. Exposed at runtime as `useRuntimeConfig().public.mobileApp` so app code can branch on it where needed. Default builds (no env var) are unchanged.

### Google OAuth in the auth modal

`ModalAuth` now renders `<AuthOAuthButtons>` for `mode === 'login' || 'signup'`, matching the `/login` page. No prop/emit changes, no new files — the existing self-contained component is reused. Caveat: OAuth success triggers a page redirect through `/oauth/callback`, so the modal's `options.onSuccess` / `redirectTo` don't fire for OAuth logins (same as `/login`). Honouring them would require stashing intent in `localStorage` alongside `oauth_state`.
