## New Features

### Admin Config page

`/admin/config` shows a read-only snapshot of everything served by `/api/v1/config` — feature flags, validation limits, LLM info — split into two cards:

- **Core**: the 15 fields declared in `CoreBackendConfig` (`app/backend/src/schemas/config.py`).
- **Sub-app extensions**: anything else returned via `build_extra()` in `config_ext.py`. Empty by default with a hint pointing at the extension file.

Booleans render as `Enabled`/`Disabled` badges, numbers and strings are monospaced, empty strings show as italic `(empty)`. The page reuses the existing `useBackendConfig` Pinia store, so no new endpoint or fetch is added.

### Shorter admin nav labels

`Organizations` → `Orgs`, `Event Logs` → `Events`, `DB Health` → `DB`, plus the new `Config` entry. The admin subnav now fits on a single line at typical widths.
