# v6.2.0

- **Released:** 2026-11-15
- **Summary:** Pseudonymous apps can turn off first and last names with `REAL_NAMES_ENABLED=false`, plus several auth UX fixes found by user testing.

## New Core Files

- `app/frontend/components/ui/PasswordInput.vue` (`UiPasswordInput`, a password field with translated show/hide labels)

## New Env Vars

- `REAL_NAMES_ENABLED` (default `true`). When `false`, signup and account settings have no name fields, names are never stored (Google sign-in included), and names already stored stop showing outside the admin. Pair it with `USERNAMES_ENABLED=true`, or users have no name to display.

## Bug Fixes

- Login and signup errors show inside the form with the fields marked invalid, not only in a toast. Apps calling `login`/`signup` from `useAccountActions()` without the new optional argument keep the toast
- The "too many requests" message no longer says "in a few minutes", which was wrong for daily caps
- Account settings show whether the email is verified, with a button to resend the verification email. Resend errors now reach the user
- Focus moves to the login link after logout instead of being lost
- The login page's show/hide password label was hard-coded in English, and most other password fields had none

## Upgrade Notes

No breaking changes for app-owned code in a default setup. Behaviour changes to know about:

- The logged-in view of the auth modal shows the user's display label instead of first and last name
- The inviter's name on invitations uses the display label
- If the verification email fails to send right after signup, the user now sees an error toast
- `passwordVisibility` is gone from `useAuthForms()`. If an app-owned component used it, switch to `<UiPasswordInput>`
- App-owned layouts should wrap their content in `<UApp :locale="uiLocale">` (from `useAppLocale()`), or Nuxt UI's own labels stay in English
