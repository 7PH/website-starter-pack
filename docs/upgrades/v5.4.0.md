# v5.4.0

- **Released:** DRAFT
- **Summary:** CMS mode for content sites (off by default): an editor role, a photo library and pages built from templates declared in code. Also two backup restore fixes and an upload logging crash fix that apply to every app.

## Upgrade Notes

With `CMS_ENABLED` unset, your app's public routes, API routes, sitemap, robots.txt and backup files stay the same. You still have to:

- **Regenerate types**: `./scripts/_core/convert-models.sh`, then commit `types/models.json` and `types/models.ts`. Without it, typecheck fails on the new CMS components.
- **Commit the merged `app/frontend/package.json`**: it gains three `@tiptap/*` deps. `@nuxt/ui` already ships them, so the lockfile only changes its root entry after `npm install`.
- **Rebuild both images**: Pillow (`>=11`) is a new backend dependency. It is only imported when a photo is processed, so CMS-off apps never load it.

What changes even with the flag off:

- `create_all` creates three empty tables on the next start: `cms_editors`, `cms_media`, `cms_pages`. No existing table is altered. The `cms` migration is only for apps that create tables by hand.
- Five admin routes exist (`/admin/cms/pages`, `/admin/cms/pages/:id`, `/admin/cms/fixed/:key`, `/admin/cms/preview/:id`, `/admin/cms/media`). With the flag off they return 404 through the `cms` middleware. In an app with its own catch-all page, these URLs used to land on that catch-all.
- `/config` gains `cms_enabled`. Backup listings gain `media_filename` and `media_size` (null with the flag off).
- Backups page: icon buttons get accessible names and the restore dialog wording changes.
- Admin: a grouped, collapsible sidebar (a drawer on phones) replaces the banner and pill nav. `middleware/admin.ts` gives every `/admin/**` page the new `admin` layout, whatever layout the page sets. `<AdminPageBanner />` and `<AdminSubnav />` still exist but render nothing, so app pages keep working; you can drop them. `PROJECT_ADMIN_NAV` items land in a "Project" group; set the new `group` field (`content`, `people`, `system`, or any name) to place them elsewhere, and `badge`/`badgeTone` for a count.
- Admin pages are redesigned on a shared pattern (`AdminPageHeader`, `AdminToolbar`, `AdminCard`, `AdminPagination`). Users: delete moved to the user page (Danger zone), single-choice filters (All / Admins / Premium / Access code) replace the yes/no selects. The organization detail component is shared, so the user-facing `/organizations/:id` page gets the new header and tabs too.
- `GET /admin/users` accepts `auth_method` (eg `access_code`) and, with CMS on, `cms_editor` (the users list gets an "Editors" segment).
- **Error page**: a core `error.vue` (seeded only when your app has none, never overwritten) shows 404 and other errors in the site layout, in French or English, with a button back home and `noindex`. Without it, visitors got Nuxt's default English page. `layouts/default.vue` gains a slot (falling back to `<NuxtPage />`) so the error page can use it.
- Previews: the `static` service serves the backend's `backend_static` volume (it served an empty `./static` before), and `STATIC_ORIGIN` is set to `https://static-<host>`, which also changes the CSP `img-src` in previews.

New env vars: `CMS_ENABLED` (default `false`, also passed to the frontend build) and `STATIC_ORIGIN` (empty keeps `static.` + `PUBLIC_URL`).

## New Features

### CMS mode (`CMS_ENABLED`)

See the README section "CMS mode". In short:

- **Editor role**: an admin turns a user into a CMS editor from the user page. Editors only reach `/admin/cms/**` (Pages, Photos), checked on the backend with `get_current_cms_editor`. Stored in `cms_editors`, never in the JWT.
- **Photo library**: JPEG, PNG, WebP up to 15 MB and 40 MP. Each upload becomes WebP at 480/960/1600/2400 px, rotated, converted to sRGB, all metadata stripped, original not kept. Alt text, focal point, delete refused while a page uses the photo. Files live in `static/cms/media/<id>-<token>/`: the random token keeps photos of drafts unguessable.
- **Pages**: templates in the app-owned `cms_templates_ext.py`. Fixed templates (one page each, read with `useCmsFixed`) and free templates (pages at `/<slug>` with SSR, SEO tags and sitemap entries). Rich text with TipTap, sanitized on save. Reserved addresses (`api*`, `admin*`, core routes) are refused. App routes always win; an app with its own top-level dynamic page (`pages/[slug].vue`, `pages/[...slug].vue`) gets a build warning and should render CMS pages itself with `useCmsPage`.
- **Listing pages**: `useCmsPageList(template)` lists the published pages of one template in the order the editor sets, or newest first with `{ order: 'published_at' }` (`GET /cms/pages?template=…&order=published_at`). There is no separate blog: a blog is a `post` template listed that way.
- **Importing content**: `PATCH /cms/admin/pages/{id}` accepts `published_at`, so an import script can keep each post's original date. Without it, a page is dated when it goes online.
- **No silent overwrites**: page saves send the `updated_at` they loaded and get a 409 if the page changed since (another tab, a quick edit). The editor then offers to reload.
- **Editing comfort**: live preview of unsaved changes, a Visual/HTML toggle in the rich text editor, and quick edit on the page itself with `<CmsEditable>` (pencil + modal per field, only for people who can edit, never in the admin).
- **Backups** also archive `static/cms/` as `cms_media_<stamp>.tar` (photos are already compressed, so no gzip) next to each dump and restore both.
- **Only with the flag on**: `/about/` gets a 301 to `/about` (query string kept), and `<html lang>` follows the site's language.

## Bug Fixes

### The events date filter did nothing

`GET /admin/events` ignored `from_date` and `to_date`. Both are now applied.

### Restoring the oldest backup could empty the database

The pre-restore safety backup ran retention, which could delete the very backup being restored. The restore then dropped every table and failed to read the dump. Retention now never deletes the restore target, and the dump is read before any table is dropped.

### Uploads crashed with INFO logging

`helpers/file_upload.py` passed keyword arguments to the standard logger, which raises `TypeError` when INFO is enabled. Both calls now use f-strings.
