# v6.12.0

- **Released:** 2026-11-27
- **Summary:** A `signup` analytics event, emails that no longer vanish over a context key's name, and the invitee's email kept out of the login URL.

## New Core Files

- `app/backend/tests/test_email_render.py`

## Features

- Core fires `signup` through `useAnalytics()` when an account is created, with `{ method: 'password' }` or `{ method: 'google' }`. A Google sign-in to an existing account doesn't count: `POST /oauth/google/callback` now returns `is_new_user`

## Bug Fixes

- An email whose template context had a key called `name` (or `app_name`, `public_url`) failed to render, and the error was only a one-line warning, so the email silently never went out. Any key now renders, and a failed send is logged with its traceback. A missing mail service stays a plain warning
- Opening an invitation while logged out put the invitee's email in the login URL, where analytics, referrers and logs could see it. The parameter was never read, so it's gone

## Upgrade Notes

No migration, no breaking change.

- `send_email` raises `EmailNotConfiguredError` (a `ValueError`) without a mail service. Code catching `ValueError` keeps working
- An analytics provider set up in `config/analytics-ext.ts` starts receiving `signup` events
