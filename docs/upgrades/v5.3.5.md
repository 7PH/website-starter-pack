# v5.3.5

- **Released:** 2026-10-07
- **Summary:** Patch. Access code sign-in forgives how pupils type codes and explains failures in place.

## Upgrade Notes

**No action required.** No schema, API, or migration changes.

## Bug Fixes

### Codes typed in lowercase were rejected

`resolve_code` compared codes exactly, so `289zz` failed for `289ZZ`, and phone keyboards lowercase by default. Typed codes are now read the Crockford way: any case, `O` as `0`, `I` and `L` as `1`, spaces and dashes ignored (`normalize_code` in `crud/access_codes.py`). The code input also sets `autocapitalize="characters"` and `spellcheck="false"`.

### Sign-in errors faded away in English

A wrong code showed a corner toast "Une erreur est survenue / Invalid code" that disappeared before a pupil read it. On `/c/<token>`, a wrong code (401) or too many attempts (429) now shows a French message under the code field, cleared when the pupil types again. Other errors still use the toast.
