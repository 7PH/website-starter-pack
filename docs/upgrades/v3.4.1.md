# v3.4.1

- **Released:** 2026-05-07
- **Summary:** Stripe price metadata is now surfaced 1:1 on `StripePlan` and `OrganizationPlan` so sub-apps can label plans with arbitrary keys (tier, seat quota, feature flags) without duplicating that data via env vars. Drops three env vars that were no longer read by any code, fills two gaps the backend was reading but neither `.env.template` nor `.env.ci` declared, and brings `.env.ci` to parity with `.env.template`.

## Upgrade Notes

No breaking changes for sub-app callers. One pre-announced removal lands.

### Migration

- **`STRIPE_PRICING_FREE` env var is gone.** It was deprecated in v3.4.0 and the constant + fallback in `helpers/stripe.py:create_subscription` is removed in this release. If any of your code calls `create_subscription(stripe_id)` without a `price_id`, it will now fail — pass an explicit price ID. (No starterpack code path called it that way after v3.4.0; sub-apps that copied the auto-create-free-sub pattern need the same edit.)
- **`TOKEN_HASH_ALG` and `USERS_PASSWORD_HASH_SECRET_KEY` are gone from `.env.template`.** Neither was read by any code. Drop them from your sub-app `.env` if present.

## New Features

### Plan metadata passthrough

`get_price_details()` now returns the full Stripe Price metadata as `dict[str, str]`, which both `StripePlan` and `OrganizationPlan` expose as a new `metadata` field. `OrganizationPlan.seats` is unchanged (still typed as `int`) — `metadata` is added in parallel.

Frontend example:

```ts
const plans = await api.get<StripePlan[]>('/stripe/plans');
const tier = plans[0].metadata.tier; // whatever key you set in the Stripe dashboard
```

Set the keys you care about on each Price in the Stripe dashboard (`Products → Price → metadata`). Backend doesn't validate keys — it's a passthrough.

### `.env.template` hygiene

Two env vars the backend reads but were never declared are now in the template:

- `ORG_INVITATIONS_ENABLED=false` — gates org invitation feature.
- `ORG_INVITATION_EXPIRY_DAYS=7` — invitation TTL.

Three vars that no code reads are removed: `TOKEN_HASH_ALG`, `USERS_PASSWORD_HASH_SECRET_KEY`, `STRIPE_PRICING_FREE`.

### `.env.ci` parity

`.env.ci` now declares everything `.env.template` declares (defaults match), so CI runs the stack with explicit values rather than implicit defaults. The "up" job exercises the full env block end-to-end.

## Bug Fixes

None — additive feature plus pre-announced cleanup.

## Known Issues

`docker-compose.core.yml` doesn't forward `ORG_INVITATIONS_ENABLED` to `NUXT_PUBLIC_ORG_INVITATIONS_ENABLED`, so the frontend always sees it as falsy regardless of the backend value. Tracked as a separate fix.
