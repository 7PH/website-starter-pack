# v6.0.0

- **Released:** 2026-11-07
- **Summary:** Umami is gone from core. Analytics now works with any provider, set up in an app-owned `config/analytics-ext.ts`. Every app drops ~1 GB of images and a second Postgres.

## Breaking Changes

### Umami removed

The `umami` and `umami-db` services, their Traefik routes, the preview overrides, the `UMAMI_*` and `NUXT_PUBLIC_UMAMI_*` env vars, the "Analytics" line of the dev banner and the admin nav link are gone. Each app ran its own Umami (a ~1 GB image plus its own Postgres) even with analytics off, and its UI didn't hold up on bigger sites.

### Analytics set up in `config/analytics-ext.ts`

Point your app at any provider (Plausible, Umami, Rybbit, Matomo, GA...), hosted or self-hosted elsewhere. The file exports `ANALYTICS`:

- `scripts`: head script entries, either a `src` with its attributes or `innerHTML` for inline init code. Added to every page.
- `origins`: added to the CSP `script-src` and `connect-src`. List every host the provider loads from or sends events to.
- `track`: called by `useAnalytics().trackEvent()`, client-side only.

```ts
export const ANALYTICS: AnalyticsConfig = {
    scripts: [{ src: 'https://plausible.io/js/pa-XXXX.js', defer: true }],
    origins: ['https://plausible.io'],
    track: (name, data) => window.plausible?.(name, { props: data }),
};
```

It's read at build time: rebuild the frontend after changing it (in dev, restart the frontend container). Empty `scripts` (the default) means no analytics.

## New Core Files

- `app/frontend/config/analytics-ext.ts` (template, app-owned once seeded)
- `app/frontend/types/analytics.ts`

## Upgrade Notes

1. **Move your tracker into `config/analytics-ext.ts`.** Core never injected the Umami tag, so if your app tracks visitors, it adds the tag itself somewhere (`app.vue`, a plugin, `useHead`). Move it to `scripts`, list its origins and set `track`, then delete the old tag or it loads twice. For Umami: `track: (name, data) => window.umami?.track(name, data)`, plus a `declare global` for `window.umami`.
2. **Delete the `UMAMI_*` and `NUXT_PUBLIC_UMAMI_*` vars** from `.env`. They're ignored now.
3. **Move the dashboard link** (was `NUXT_PUBLIC_UMAMI_DASHBOARD_URL`) to `PROJECT_ADMIN_NAV` in `config/admin-nav-ext.ts`, with `href` and `external: true`.
4. **Run `npm run stop` once** after upgrading. Its `--remove-orphans` removes the old `umami` and `umami-db` containers.
5. **Keeping your self-hosted Umami?** Copy the two services from the previous `docker-compose.core.yml` into your `docker-compose.yml` and its routers into `services/traefik/dynamic.yml`. Otherwise export what you need first: the data stays in `services/umami/data` (root-owned) until you delete it.
