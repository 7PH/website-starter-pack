# v3.6.0

- **Released:** 2026-05-16
- **Summary:** Pre-rewrite hardening pass. Backend gets prod-ready defaults (DB timeouts, cluster-singleton scheduler, trusted-proxy real-IP, multi-worker uvicorn). Frontend gets two new extension hooks: `SITEMAP_ENABLED` lets high-scale sub-apps own `/sitemap.xml` themselves; `config/route-rules-ext.ts` lets sub-apps add legacy-URL 301s and SSR caching (`swr`) without forking `nuxt.config.ts`. New `/internal/seed-users` endpoint + `npm run seed-preview-users` provision a deterministic user roster for PR preview stacks.

## Upgrade Notes

**Mostly non-breaking.** Defaults are conservative so existing single-worker, single-locale, English-URL sub-apps see zero behaviour change.

The one behaviour change worth knowing about: every DB connection now carries `statement_timeout=30s` and `idle_in_transaction_session_timeout=30s` server-side. Queries or transactions that legitimately need longer must opt in via `DB_STATEMENT_TIMEOUT_MS` / `DB_IDLE_IN_TRANSACTION_TIMEOUT_MS` (set to a larger value, or `0` to disable). 30s is generous for OLTP — if you have endpoints that exceed it, that's almost always a query to fix, not a timeout to relax.

To go multi-worker, set `BACKEND_WORKERS=4` (or higher) and `TRUSTED_IP_HEADER=X-Forwarded-For` in `.env`. The core cron jobs (backups, billing) already use cluster-singleton locks so they only run on one worker.

## New Core Files

- `app/backend/src/helpers/real_ip.py` — `RealIPMiddleware` + `get_real_ip(request)` helper. Reads `TRUSTED_IP_HEADER`, takes the rightmost entry (Traefik appends by default, so leftmost is client-spoofable), stamps on `request.state.real_ip`.
- `app/frontend/config/route-rules-ext.ts` (`:template`) — exports `ROUTE_RULES_EXT`; spread into `nuxt.config.ts` `routeRules` with starter rules winning on conflict.
- `scripts/_core/seed-preview-users.sh` — wrapped by `npm run seed-preview-users`. Calls `/internal/seed-users` with a roster from `.env.preview.app` (default: admin / user / premium).

## New Features

### Backend prod-readiness knobs

- **`DB_STATEMENT_TIMEOUT_MS`** (default `30000`) — server-side `statement_timeout` via libpq `options`. `0` disables.
- **`DB_IDLE_IN_TRANSACTION_TIMEOUT_MS`** (default `30000`) — server-side `idle_in_transaction_session_timeout`. `0` disables.
- **`BACKEND_WORKERS`** (default `1`) — uvicorn `--workers` for `backend-prod`. Compose interpolates at parse time so uvicorn stays PID 1 and SIGTERM propagates cleanly. Going above 1 requires every scheduled job to use a cluster-singleton lock; the core jobs already do.
- **`TRUSTED_IP_HEADER`** (default empty) — header to read the real client IP from. Empty = use `request.client.host`. Rate-limit keys and event-log IPs both route through `get_real_ip()`, so flipping this alone fixes both surfaces.

### Cluster-singleton scheduler primitive

`tasks/_scheduler.py::_run_once_per_cluster(lock_id, log_name, fn)` wraps a function in a `pg_try_advisory_lock` so only one worker / pod runs it per tick. `register_cron_task(..., cluster_lock_id=...)` opts a job in. Hand-picked IDs live in `tasks/__init__.py::CORE_LOCK_ID_*`; sub-apps adding their own cluster-locked jobs should pick IDs outside `71500000-71509999`. Lock-acquisition transaction is committed immediately so the idle-in-tx timeout can't kill the session mid-job; the connection is invalidated on unlock failure so a still-locked connection never rides the pool back out.

### `SITEMAP_ENABLED` build flag

For apps whose sitemap pipeline doesn't fit `@nuxtjs/sitemap`'s runtime generation model — precomputed XML on disk, cron-driven indexing, 100K+ URLs. Set `SITEMAP_ENABLED=false` in `.env` and the module registers no `/sitemap.xml` route. The sub-app then serves it however they want: a file in `app/frontend/public/sitemap.xml` (Nitro's static-asset handler shadows the now-disabled module), a custom `server/routes/sitemap.xml.ts`, or upstream Nginx. `robots.txt` still emits `Sitemap: <baseUrl>/sitemap.xml` — the sub-app is responsible for keeping that URL reachable.

The flag is wired as a build arg (`Dockerfile.prod-node`) for the prod build and as a runtime env for the dev container.

### `route-rules-ext.ts` extension hook

`nuxt.config.ts` now spreads `ROUTE_RULES_EXT` from `config/route-rules-ext.ts` into its `routeRules` block. Sub-apps express both 301 redirects and SSR caching through this single hook:

```ts
export const ROUTE_RULES_EXT = {
    // Preserve a legacy URL after a rename
    '/old-pricing': { redirect: { to: '/pricing', statusCode: 301 } },
    // Cache a slow page for 1h with stale-while-revalidate
    '/media/**': { swr: 3600 },
    // Prerender a stable page at build time
    '/about': { prerender: true },
} satisfies NitroConfig['routeRules'];
```

`swr` caches the rendered HTML server-side (nitro emits `Cache-Control: s-maxage=<ttl>, stale-while-revalidate`); subsequent hits skip the render entirely. Measured on starter dev with a 400ms server-side sleep: cold 484ms → warm 12ms (≈40× speedup). No additional nitro cache-driver config needed for this to work.

Starter's own routeRules (security headers, `/admin/**` SSR-off, etc.) win on conflict — sub-app overrides for those keys are silently dropped. If you genuinely need to override a starter-shipped rule, file an issue.

### `/internal/seed-users` + preview-stack seeding

`POST /api/v1/internal/seed-users` upserts a deterministic user roster (admin / user / premium by default, with `preview-<role>` passwords). Gated by `INTERNAL_API_KEY`; the route is unregistered when the key is empty.

`npm run seed-preview-users` wraps the endpoint. The CI preview workflow (`.github/workflows/preview.yml`) calls it after the preview stack boots so PRs always have known credentials. Sub-apps can override the roster via `PREVIEW_SEED_USERS` in `.env.preview.app` (commented schema in the template).
