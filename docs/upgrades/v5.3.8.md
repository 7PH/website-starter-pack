# v5.3.8

- **Released:** 2026-10-17
- **Summary:** Patch. Prod builds get `PUBLIC_URL` again, Umami's tracker works past basic auth, and the sitemap e2e test accepts a sitemap index.

## Upgrade Notes

**No action required.** No migration, no schema or API change. The next `npm run start` rebuilds the prod frontend images with the fix.

- Apps that worked around the empty base URL with `NUXT_PUBLIC_BASE_URL` can drop it once rebuilt.

## Bug Fixes

### Prod builds had an empty `PUBLIC_URL`

`nuxt.config.ts` reads `PUBLIC_URL` and a few other env vars at build time, but the prod Dockerfiles only got `SITEMAP_ENABLED` as a build arg. So in prod, robots.txt served `Sitemap: /sitemap.xml`, breadcrumb JSON-LD had relative URLs, and the CSP had no static or Umami origin. Both prod frontend images now get `PUBLIC_URL`, the app name, the default locale and the Umami flag and subdomain, from one shared list so the two builds can't drift.

### Umami's tracker was behind basic auth

Visitors couldn't load `/script.js` or post to `/api/` on the analytics subdomain. Those two paths now skip basic auth, the dashboard keeps it, and its rate limit is gone.

### The sitemap e2e test rejected a sitemap index

Apps with more than 50k URLs need `/sitemap.xml` to be a sitemap index. The core seo test now accepts `<sitemapindex>` as well as `<urlset>`.
