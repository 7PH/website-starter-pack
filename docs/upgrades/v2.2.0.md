# v2.2.0

- **Released:** 2026-04-27
- **Summary:** Override hooks for `PageHeader` and `PageFooter` so sub-apps can replace the site chrome via the existing `componentOverrides` map.

## Upgrade Notes

No breaking changes. The default header and footer continue to render unchanged when no override is registered.

### Migration

None.

## New Features

### Overridable header and footer

`layouts/default.vue` and `layouts/fullheight.vue` now wrap `PageHeader` and `PageFooter` in `useOverridable()`. Sub-apps register replacements via the existing map in `app/frontend/config/component-overrides.ts`:

```ts
export const componentOverrides: Record<string, AsyncComponentLoader> = {
    PageHeader: () => import('~/components/MyAppHeader.vue'),
    PageFooter: () => import('~/components/MyAppFooter.vue'),
};
```

The override component must mirror the original's contract (no public props/events; it consumes `useAuth`, `useStripe`, `useAppLocale`, `useColorModeToggle`, etc. directly).

Use cases this unblocks:
- Marketing surfaces that need theme + locale toggles available to logged-out visitors (the default header gates the settings dropdown behind login).
- Sub-app branding without forking the layout file.
