# v6.11.1

- **Released:** 2026-11-27
- **Summary:** Organization member lists and conversations no longer fail on users without a name or email.

## New Core Files

- `app/backend/tests/test_null_names.py`

## Bug Fixes

- `GET /organizations/{id}/members` (and the organization page) returned a 500 when a member had no first or last name, eg a seeded user, a pseudonymous app or a Google account without a family name. `OrganizationMemberRead.first_name` and `last_name` are now nullable
- Conversations failed the same way for a participant without a name or an email (managed accounts, deleted users). `ConversationUserPreview.email`, `first_name` and `last_name` are now nullable
- The members table no longer shows "null null" for such a member

## Upgrade Notes

No migration. App code reading these fields as plain strings should handle `null` (the generated types now say so).
