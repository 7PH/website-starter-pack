# v4.0.0

- **Released:** 2026-06-15
- **Summary:** Prod-readiness hardening from a sub-app audit — rate limiting moves to a mandatory Redis service, the admin guard re-checks the DB, a default Content-Security-Policy ships, and version/disclosure headers are stripped. Plus a host reverse-proxy wizard and editor config. Two breaking changes: Redis is now required, and the CSP is on by default.

## Breaking Changes

### Redis is now required

Rate limiting (login, register, password reset, bug reports, etc.) is now backed by Redis instead of a per-worker in-memory dict, so the per-IP cap is global across workers/instances. A `redis` service is included in `docker-compose.core.yml`, and `REDIS_URL` (default `redis://redis:6379/0`) is in `.env.template`.

If Redis is unreachable, rate-limited endpoints **fail closed with `503`** (never silently unthrottled). After upgrading you **must** run the Redis service and set `REDIS_URL`, or auth endpoints will return 503.

- `core-update.sh` brings the `redis` service and `REDIS_URL` into your stack.
- Self-hosted/custom compose setups must add a reachable Redis and `REDIS_URL`.

### Content-Security-Policy is on by default

The frontend now ships a default CSP, built from env so your static-media and analytics (umami) origins are injected automatically. Any **other** external origin your app loads (scripts, styles, fonts, images, API calls) will be blocked until you allow it.

- Override or extend in `app/frontend/config/security-headers.ts` (`SECURITY_HEADERS_OVERRIDE`); set `Content-Security-Policy` to `''` to remove it.
- Per-route exceptions (e.g. `/embed` needing `frame-ancestors *`) go in `config/route-rules-ext.ts` at a path more specific than `/**`.
- After upgrading, load your app in a browser and check the console for CSP violations.

## Security

- **Admin guard re-checks the DB.** `get_current_admin` resolves the user from the DB instead of trusting the JWT `is_admin` claim, so a demoted admin loses access immediately instead of until token expiry (mirrors `require_premium`).
- **Login brute-force throttle is now global.** The old in-memory limiter was per-worker, so `BACKEND_WORKERS>1` gave an effective cap of N× the configured value. The Redis-backed limiter shares one bucket.
- **Email enumeration on register** is a documented, accepted tradeoff (a signup form must report a taken email); the per-IP register rate limit throttles bulk probing.

## Hardening

- `Server` (uvicorn) and `X-Powered-By` (Nuxt) headers removed; nginx `server_tokens off`.
- The static media host now sends `X-Content-Type-Options: nosniff`.

## New Core Files

- `services/static/nginx.conf` — security headers for the static host.
- `app/frontend/server/plugins/strip-headers.ts` — removes `X-Powered-By`.
- `scripts/_core/setup-host-proxy.sh` — `npm run setup-host-proxy` wizard for nginx + real-client-IP.
- `docs/deployment/reverse-proxy.md` — reverse-proxy topologies and setup.
- `.vscode/{extensions,launch,settings}.json` — editor config, seeded as templates.

## Upgrade Notes

1. Run `bash scripts/_core/core-update.sh` (or `/upgrade-starterpack`).
2. Ensure Redis runs and `REDIS_URL` is set (default works with the bundled service).
3. Review the CSP against your app's external origins; adjust via `config/security-headers.ts`.
4. Optional: `npm run setup-host-proxy` if a host nginx fronts the stack; set `PUBLIC_BIND_HOST=127.0.0.1` (see `docs/deployment/reverse-proxy.md`).
