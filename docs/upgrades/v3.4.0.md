# v3.4.0

- **Released:** 2026-05-07
- **Summary:** Single typed event-bus for all starterpack hooks (`@on(EventClass)`), new `SubscriptionChanged` hook for Stripe events, group-management policy now also gates managed-account routes, drops the auto-create-free-sub wart in favor of an explicit Subscribe / Manage split that mirrors the org flow, and a `UserReadAssembled` hook that lets sub-apps append app-side fields to `UserRead.extra` without a separate `/me` round-trip.

## Upgrade Notes

Three breaking changes. Migration paths below.

1. **Auto-create-free-sub is gone.** `GET /stripe/portal` now returns 400 when the user has no active subscription. The frontend sends users through the new `POST /stripe/checkout` flow first. New sign-ups still get a Stripe customer record (so checkout is fast) but no subscription.
2. **Managed-account routes now run through the group-management policy.** Apps that registered a tier-gated policy will see the same gate apply to every managed-account write (create, edit, delete, reissue-code, open-as). The default policy still allows everyone, so apps without a registered policy see no change.
3. **`set_group_management_policy` and `register_code_validator` are deprecated.** They keep working with a `DeprecationWarning` for v3.4.x and will be removed in v3.5.0.

### Migration

#### 1. Migrate `set_group_management_policy` → `@on(GroupManagementCheck)`

Before:

```python
from .helpers.policies import set_group_management_policy

def can_manage(user):
    return user.is_premium and user.subscription_tier == "teacher"

set_group_management_policy(can_manage)
```

After:

```python
from sqlalchemy.orm import Session
from .helpers.hooks import GroupManagementCheck, on

@on(GroupManagementCheck)
def my_policy(session: Session, event: GroupManagementCheck) -> None:
    if not is_teacher(session, event.user):
        event.allow = False
```

#### 2. Migrate `register_code_validator` → `@on(AccessCodeResolution)` (or use the helper)

Default access-code lookup. Before:

```python
from .helpers.access_codes import default_access_code_validator
from .helpers.auth import register_code_validator
register_code_validator(default_access_code_validator)
```

After:

```python
from .helpers.access_codes import register_default_access_code_resolver
register_default_access_code_resolver()
```

Custom resolver. Before:

```python
from .helpers.auth import register_code_validator
register_code_validator(my_validator)  # (account_id, code, request) -> UserBase | None
```

After:

```python
from sqlalchemy.orm import Session
from .helpers.hooks import AccessCodeResolution, on

@on(AccessCodeResolution)
def my_resolver(session: Session, event: AccessCodeResolution) -> None:
    if event.user is not None:
        return  # earlier handler already resolved
    event.user = my_lookup(event.managed_account_id, event.code, event.request)
```

#### 3. Drop the auto-free-sub workarounds

Two changes likely live in your app's Stripe handlers:

- The `unit_amount > 0` filter that ignored shell subs — still safe to keep, but no longer needed for the user-flow side. Org subs are unaffected.
- Any code that assumed every Stripe-enabled user had a subscription after first portal open — that assumption is gone. Send users to `POST /stripe/checkout` instead.

If you set `STRIPE_PRICING_FREE`, you can stop. The env var is read for backward compatibility but no starterpack code references it anymore. It will be deleted in a future release.

## New Features

### Typed event-bus (`helpers/hooks.py`)

One pattern for every hookable point. Apps register handlers from `main_ext.py`:

```python
from .helpers.hooks import SubscriptionChanged, on

@on(SubscriptionChanged)
def my_tier_sync(session, event: SubscriptionChanged) -> None:
    if event.user is None or event.action == "deleted":
        return
    upsert_tier(session, event.user.id, ...)
```

Discoverability: every hookable point is a `HookEvent` subclass in `helpers/hooks.py`. IDE go-to-definition on the event class shows the full schema. Find-all-subclasses lists every hook.

The four shipped events:

- `SubscriptionChanged` — Stripe `customer.subscription.{created,updated,deleted}`. Observe-only; the starterpack's own writes are already done.
- `GroupManagementCheck` — fired before any group OR managed-account write. Set `event.allow = False` to deny.
- `AccessCodeResolution` — fired by `POST /auth/code`. Set `event.user = ...` to resolve.
- `UserReadAssembled` — fired in `build_user_read_with_orgs` (which feeds both JWT mints and `GET /users/me`). Append fields to `event.extra`; they appear in `auth.user.extra` on the frontend.

Conventions:

- Handler signature: `(session: Session, event: E) -> None`. No return values.
- Errors are logged and swallowed — one bad app handler must not break the request.
- Single-result events expose a named mutable field. Multi-handler events are observe-only.
- Stripe may replay events. Make handlers idempotent in shape (`ON CONFLICT`, `UPDATE ... WHERE`).

### `POST /stripe/checkout` for individual users

Mirrors `POST /organizations/{id}/checkout`. Takes a `price_id` from a configurable allowlist (`USER_STRIPE_PRICE_IDS`), creates a Stripe-hosted checkout session, returns the URL.

```env
USER_STRIPE_PRICE_IDS=price_individual_monthly,price_individual_annual
```

The new `GET /stripe/plans` endpoint returns the configured plans (price, name, currency, interval).

### `UserRead.extra: dict[str, Any]`

Fired in `build_user_read_with_orgs` so app-side fields land in every `UserRead` (login response, refresh-token response, `GET /users/me`). Replaces the round-trip many sub-apps were doing for tier display.

```python
@on(UserReadAssembled)
def expose_tier(session, event):
    sub = get_app_subscription(session, event.user.id)
    if sub:
        event.extra["app_tier"] = sub.tier
        event.extra["app_seat_quota"] = sub.seat_quota
```

Frontend reads `auth.user.extra.app_tier`. No new API call needed.
