# v3.0.0

- **Released:** 2026-04-28
- **Summary:** Component overrides now take Vue components directly instead of async loader functions. Fixes an intermittent SSR/hydration race where the loader could resolve on one side but not the other, causing `insertBefore` crashes when the override and default rendered different DOM shapes.

## Upgrade Notes

### Migration

**Required for sub-apps that have entries in `app/frontend/config/component-overrides.ts`.** The override map type changed from `Record<string, AsyncComponentLoader>` to `Record<string, Component>`. The `AsyncComponentLoader` type is removed.

For each registered override, replace the async loader with a top-level import:

```diff
+import MyHeader from '~/components/custom/MyHeader.vue';

-export const componentOverrides: Record<string, AsyncComponentLoader> = {
-    PageHeader: () => import('~/components/custom/MyHeader.vue'),
-};
+export const componentOverrides: Record<string, Component> = {
+    PageHeader: MyHeader,
+};
```

For genuinely heavy overrides where lazy loading matters, wrap the import with Vue's `defineAsyncComponent` instead — `useOverridable` will hand it back to Vue, which handles SSR/Suspense correctly:

```ts
import { defineAsyncComponent } from 'vue';

export const componentOverrides: Record<string, Component> = {
    BigModal: defineAsyncComponent(() => import('~/components/custom/Big.vue')),
};
```

### New environment variables

None.

## Bug Fixes

- Resolved intermittent hydration crashes (`insertBefore`) when an override component had a different scoped-style hash or comment count than the default. Root cause: the async loader could resolve before render flush on SSR but not on the client (or vice versa), producing diverging vdom. Fixed by removing async resolution from the override path entirely.

## New Core Files

- `.mcp.json` — Playwright MCP config now syncs from the starterpack so sub-apps stay aligned. If you had a customized `.mcp.json` with extra MCP servers, move those servers to a user-level Claude Code config (`~/.claude.json`) before upgrading; the file will be overwritten on sync.
