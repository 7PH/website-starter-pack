## Upgrade Notes

**No breaking changes.** No schema or migration changes.

**Translated your emails in `templates/email/`?** That folder syncs from the starterpack and gets overwritten. Move your versions to `app/backend/src/templates_app/email/` (same file names) before or right after upgrading. Files there win over the core ones.

**Checkout success URL changed** to `/account?tab=billing&subscription=success` (cancel: `...&subscription=canceled`). If your app reads `?subscription=` somewhere else, update it.

## New Features

### App-owned email templates and subject lines

`helpers/email.py` now looks in `app/backend/src/templates_app/email/` first, then in the core `templates/email/`. An optional `<name>.subject` file there overrides the built-in English subject (Jinja, same context as the body, e.g. `Réinitialisez votre mot de passe`). Blank or missing falls back to the default.

### Prices in the UI locale

`usePriceFormat()` formats plan prices with `Intl.NumberFormat` in the current locale and reads billing intervals from `core.billing.interval.*`. French now shows `8,00 € / mois` instead of `€8.00 /mo`. Used by the subscribe modal, the organization subscription modal and the organization billing tab. `formatPrice()` takes an optional locale (default `en-US`, unchanged).

### Checkout returns to the billing tab

After Stripe Checkout, users land on the billing tab, which shows a success (or canceled) toast, drops `?subscription=` from the URL and re-syncs premium from Stripe. The nav's premium badge updates without a reload. Before, users landed on the account tab, saw nothing, and the nav kept saying "Upgrade" until a refresh.

### Bulk import detects "MARTIN Alice"

The paste-a-list import ticks "Last name first" by itself when most lines start with an ALL-CAPS word followed by one that isn't, the usual school-export format. Unticking it sticks until the modal reopens.

## Bug Fixes

- The access-code placeholder showed `AB32`, but generated codes have 5 characters. It now shows `K7M4P`.
- Switching between login, sign-up and forgot-password on `/login` now updates `?mode=`, so reloading or going back keeps the same form, and layouts can read the current mode.
