# v3.4.2

## New Features

### `ManagedAccountSeatGate` hook

The existing `GroupManagementCheck` hook gates **whether** a user can manage groups at all. `ManagedAccountSeatGate` gates **how many** accounts they can create — the missing piece for sub-apps that ship multiple paid tiers (e.g. Teacher 10 vs Teacher 50) with seat quotas baked into Stripe price metadata.

The starterpack-level `MANAGED_ACCOUNTS_MAX_PER_USER` env cap still runs first as a global guardrail (still returns 400). The new hook layers per-tier rules on top and returns 402 when denied.

```python
from sqlalchemy.orm import Session

from .helpers.hooks import ManagedAccountSeatGate, on


@on(ManagedAccountSeatGate)
def enforce_seat_quota(session: Session, event: ManagedAccountSeatGate) -> None:
    sub = my_app_subscription(session, event.user.id)
    if sub is None or sub.seat_quota is None:
        return  # no per-tier rule; fall through to env cap
    current = my_count_accounts(session, event.user.id)
    if current + event.count_to_create > sub.seat_quota:
        event.allow = False
        event.reason = (
            f"Your tier allows up to {sub.seat_quota} accounts "
            f"({current} already created). Upgrade to add more."
        )
```

The event payload:

- `user: UserRead` — the requesting user.
- `group_id: int` — destination group.
- `count_to_create: int` — `1` for single create, `len(payload)` for bulk (worst-case upper bound, pre-dedup; mirrors the env-cap check).
- `allow: bool = True` — set `False` to deny.
- `reason: str | None = None` — optional human-readable message that becomes the 402 response detail. Generic `"Seat quota exceeded"` is used when omitted.

### Why 402 instead of 400 / 403

- **400** is for malformed input. The request is well-formed; the user just doesn't have the seats.
- **403** says "you may never do this". They can — by upgrading.
- **402 Payment Required** is the right semantic and frontend handlers can route it to an upgrade modal without parsing detail strings.

The starterpack env cap stays at 400 (it's a global guardrail, not a paywall).

## New convention: `reason` alongside `allow`

Gate events that may want to surface a human-readable failure message now pair `allow: bool` with `reason: str | None`. Handlers set both together; the firing site uses `reason` in the error response. `helpers/hooks.py` documents this in its module docstring.
