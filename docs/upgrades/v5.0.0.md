# v5.0.0

- **Released:** 2026-09-03
- **Summary:** Remediation of a third-party security audit, plus optional usernames as a public handle and login identifier. Three changes need action when you upgrade: Umami credentials are mandatory, the internal API routes need an explicit opt-in in production, and OAuth refuses to link an unverified account.

## Breaking Changes

### Umami credentials are mandatory

`docker-compose.core.yml` no longer falls back to `umami` / `change-me-in-production`. `UMAMI_DB_PASSWORD` and `UMAMI_APP_SECRET` must be set, or **every `docker compose` command fails** with a message naming the missing variable.

Compose interpolates at parse time, so this applies even though previews disable the umami profile. `.env.template` has always carried both as `<secret:64>` placeholders; if your `.env` predates that, add them before upgrading.

### Internal routes need an opt-in in production

`/api/v1/internal/mint-token` and `/seed-users` were registered whenever `INTERNAL_API_KEY` was set — and `.env.template` generates one, so production had them behind a single shared header with no throttle.

Registration now requires the key **and** either development mode or `INTERNAL_API_ENABLED=true`. Production without the flag returns 404.

- Local dev is unchanged; `npm run dev-mint-token` keeps working.
- `docker-compose.preview.yml` sets the flag, because previews run the prod profile and seed users through these routes.
- If your production tooling calls them, set `INTERNAL_API_ENABLED=true` explicitly.

### OAuth will not link an unverified account

The Google callback auto-linked any existing account matching the email. If someone signed up with an address they never confirmed, whoever controlled that address at Google took over the account. The callback now returns **409** when `email_confirmed` is false. Dormant unless `OAUTH_ENABLED=true`.

### @nuxt/ui moves 4.3 → 4.11

Inside the declared `^4` range — only the lockfile held it back — but eight minor versions. Load your screens once after upgrading. The bump clears 43 typecheck errors on idiomatic `@click="x = true"` handlers that 4.3 rejected.

## New Features

### Usernames (`USERNAMES_ENABLED`, off by default)

An optional public handle that doubles as a login identifier alongside the email.

- 2–32 characters, `[a-zA-Z0-9_[]-]`. `@` is excluded so a handle can never be mistaken for an email in the login box, and the set stays URL-safe.
- Uniqueness is **case-insensitive**, enforced by a partial unique index on `lower(username)` — a plain `UNIQUE` would let `Bob` and `bob` coexist.
- Reserved handles are blocked; soft-deleting a user nulls the handle so it can be reclaimed.
- Case is preserved for display; admins can set a handle from the user detail page.

Turn it on with `USERNAMES_ENABLED=true`. Off, the column stays `NULL` and no UI appears.

## Security

Findings from an external audit of a sub-app, fixed upstream:

- **Internal routes off the public edge** (see Breaking Changes) and the key compared as bytes, so a non-ASCII `X-Internal-API-Key` returns 401 instead of a 500.
- **Admin surface out of the OpenAPI document.** `/api/docs` stays public, but the admin, backups, db-health and internal routers leave the schema, and OAuth/conversations follow their feature flags. The published schema went from 67 paths to 52.
- **Traefik prod profile.** `--api.insecure` and `--log.level=DEBUG` are dev-only; prod logs at INFO. The Docker socket mount is gone — only the file provider was ever used. The dashboard is now refused from inside the Docker network too, which matters on a shared preview host.
- **HSTS and an API CSP.** HSTS ships when `USE_TLS=true`; API responses carry `default-src 'none'; frame-ancestors 'none'; base-uri 'none'`. The docs pages are excluded — Swagger and ReDoc load their assets from a CDN.
- **Backup and restore no longer use a shell.** Both jobs streamed through `sh -c` with interpolated paths; they now use argv `Popen` piped through Python's gzip.
- **Password-reset links live 4 hours**, down from 7 days, stated in both email templates and in the UI. Note the token is still bound only to the user id, so within that window it survives a successful reset.
- **The account-deletion confirmation URL is redacted from production logs.** It carries a bearer token and was written out whenever the email send failed.

## Bug Fixes

- **The auth router was registered twice**, under two different tags, colliding the operation id of all eight auth endpoints in the schema. 102 registered routes → 94, with the path set unchanged.
- **`nuxt typecheck` was broken in CI** since mid-June: it shells out through `npx`, which fetched a TypeScript major that dropped the `typescript/lib/tsc` subpath vue-tsc needs. `vue-tsc` is now a pinned devDependency, so it resolves the workspace TypeScript.

## Upgrade Notes

1. **Run the migration** `2026-09-03-v5.0.0-add-user-username.sql`. `ADD COLUMN` is metadata-only, but the unique index takes a `SHARE` lock while it builds — brief on a small `users` table, not on a large one. The file documents the `CONCURRENTLY` variant. If your app already has its own `username` column, check for case-variant duplicates first; the query is in the migration header.
2. **Set `UMAMI_DB_PASSWORD` and `UMAMI_APP_SECRET`** or the stack will not start.
3. **Set `INTERNAL_API_ENABLED=true`** only if production tooling calls `/api/v1/internal/*`.
4. **Load the app in a browser** after upgrading, for the `@nuxt/ui` bump.
5. Optional: set `USERNAMES_ENABLED=true` to expose handles.
