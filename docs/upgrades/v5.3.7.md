# v5.3.7

- **Released:** 2026-10-15
- **Summary:** Patch. Access-code lockout, Stripe portal cancellations, French labels, and prod restarts that now load pulled backend code.

## Upgrade Notes

**No action required.** No migration, no schema or API change.

- Sub-apps with their own layout wrapping `<UApp>` can pass `useAppLocale().uiLocale` to its `:locale` prop to get Nuxt UI labels in the app language, like the core layouts now do.

## Bug Fixes

### The access-code lockout let the right code in

After 5 wrong codes for one account from one IP, `/auth/code` answers 429 for 15 minutes, but the right code still signed in during that time, so the lockout cost a guesser nothing. The `(IP, account)` failure bucket is now checked before the code is resolved, and every code is refused while it's locked.

### A Stripe portal cancellation still showed plain Premium

On recent Stripe API versions the customer portal sets `cancel_at` and leaves `cancel_at_period_end` false, so the billing tab never showed the end date or the "canceling" alert. A subscription with `cancel_at` now counts as canceling, and its end date comes from `cancel_at`.

### English text on non-English apps

- Signing up with an email that already has an account showed the server's raw "Email already registered". Without usernames it now shows `core.auth.emailTaken` ("Un compte existe déjà avec cet email").
- The `default`, `fullheight` and `auth` layouts now pass the app locale to `<UApp>`, so Nuxt UI's own labels ("Close", "Show password", "Increment"…) follow it.
- The header's home link is labelled with `core.common.home` instead of a hardcoded "Home".

### `npm run start` kept running the old backend code

The prod backend code is bind-mounted, so `up --build` left a code-only change running the previous code. `start.sh` now restarts `backend-prod` after `up`.
